# ClubMax
بک‌اند سامانه مدیریت باشگاه ClubMax با Go و PostgreSQL. این نسخه شامل مدیریت کاربران و نقش‌ها، ثبت باشگاه، عضویت ورزشکار و زیرساخت تأیید شماره موبایل است.

ClubMax is a gym-management platform built for coaches and athletes.

## ساختار پروژه

```text
ClubMax/
├── backend/       API، مدل‌ها، منطق دامنه و repositoryهای PostgreSQL
├── frontend/      رابط کاربری Next.js، فارسی و انگلیسی
├── clubmax.env.example  الگوی تنظیمات مرکزی IP، پورت‌ها و کلیدها
├── compose.yaml   پایگاه‌داده محلی
└── Makefile       فرمان‌های متداول توسعه
```

## اجرای محلی

1. پایگاه‌داده را با `docker compose up -d db` اجرا کنید.
2. در نصب جدید، `clubmax.env.example` را با نام `clubmax.env` کپی و IP، پورت‌ها و رمزها را در همان فایل مرکزی تنظیم کنید. اسکیمای دیتابیس هنگام شروع بک‌اند از مدل‌ها ساخته می‌شود.
3. بک‌اند را با `cd backend && go run main.go` اجرا کنید.
4. فرانت‌اند را با `cd frontend && npm install && npm run dev` اجرا کنید.

برای اجرای هم‌زمان دیتابیس، بک‌اند و فرانت‌اند می‌توانید در ریشه پروژه
`./run_project.sh` و برای توقف آن‌ها `./stop_project.sh` را اجرا کنید. در اجرای اول، وابستگی‌های فرانت‌اند در صورت نبودن به‌صورت خودکار نصب می‌شوند.

سرویس به‌صورت پیش‌فرض روی `http://127.0.0.1:8081` اجرا می‌شود. پاسخ‌های API فارسی هستند؛ برای دریافت پاسخ انگلیسی هدر `Accept-Language: en` ارسال کنید. زبان‌های پشتیبانی‌شده از مسیر `GET /v1/meta/locales` قابل دریافت‌اند.

رابط Next.js روی `http://127.0.0.1:3001/fa` اجرا می‌شود. مسیر انگلیسی `/en` است و ورود به `/` به فارسی هدایت می‌شود.

در محیط توسعه، کد OTP به‌جای ارسال SMS در log چاپ می‌شود. برای محیط production باید پیاده‌سازی `OTPNotifier` با درگاه پیامک جایگزین شود و `APP_ENV=production` باشد.

مدیر اولیه توسعه از مقادیر `CLUBMAX_ADMIN_*` در فایل مرکزی `clubmax.env` ساخته می‌شود. این مقادیر پیش از استقرار واقعی باید تغییر کنند.

## پشتیبان‌گیری

بک‌اند به‌صورت پیش‌فرض هر روز ساعت‌های 06:00، 14:00 و 23:00 به وقت ایران از PostgreSQL پشتیبان می‌گیرد. فایل‌ها در مسیر `CLUBMAX_BACKUP_DIR` با سطح دسترسی محدود ذخیره می‌شوند و به‌صورت پیش‌فرض آخرین 42 نسخه (14 روز) باقی می‌مانند. مدیر می‌تواند ساعت‌های اجرا و تعداد نسخه‌های نگهداری را از صفحه «پشتیبان‌گیری» تغییر دهد؛ تغییر زمان‌بندی بدون راه‌اندازی مجدد بک‌اند اعمال می‌شود. مقادیر `CLUBMAX_BACKUP_HOURS` و `CLUBMAX_BACKUP_RETENTION` تنظیمات پیش‌فرض و جایگزین زمان خطای دیتابیس هستند.

مدیر سایت از منوی «پشتیبان‌گیری» می‌تواند یک فایل `tar.gz` شامل خروجی پایگاه داده و `manifest.json` دریافت کند. افزودن همه تصاویر و مدارک آپلودشده با گزینه «پشتیبان‌گیری از کلیه فایل‌های آپلودشده» اختیاری است. این فایل حاوی اطلاعات حساس کاربران است و باید رمزنگاری‌شده و خارج از سرور اصلی نگهداری شود.

در همان صفحه امکان بازیابی آرشیو وجود دارد. سرور ساختار آرشیو، نسخه فرمت، نام دیتابیس، تعداد فایل‌ها و SHA-256 خروجی دیتابیس را پیش از اجرا کنترل می‌کند. بازیابی دیتابیس در یک تراکنش انجام می‌شود. اگر آرشیو شامل فایل‌ها باشد پوشه آپلودها پس از موفقیت دیتابیس به‌صورت یکجا جایگزین می‌شود؛ در آرشیو فقط‌دیتابیس، فایل‌های فعلی دست‌نخورده باقی می‌مانند. آرشیوهای نسخه قبلی نیز به‌عنوان پشتیبان کامل شناخته می‌شوند.

برای تهیه خروجی، نسخه `pg_dump` نصب‌شده روی میزبان باید با نسخه سرور PostgreSQL سازگار باشد. در محیط توسعه، اگر خروجی مستقیم ممکن نباشد، بک‌اند از کانتینر مشخص‌شده در `CLUBMAX_DATABASE_CONTAINER` استفاده می‌کند؛ در نصب بدون Docker این مقدار می‌تواند خالی باشد.

## اجرای Production با Docker

فایل `compose.production.yaml` سه سرویس مستقل و مینیمال می‌سازد: PostgreSQL 17 Alpine، بک‌اند Go و فرانت‌اند standalone نرم‌افزار Next.js. دیتابیس روی پورت عمومی منتشر نمی‌شود و فقط از شبکه داخلی Compose قابل دسترسی است. دیتابیس در volume `postgres_data` و فایل‌ها و نسخه‌های پشتیبان در volume `app_data` ماندگار هستند. log هر کانتینر نیز با گردش خودکار به سه فایل ۱۰ مگابایتی محدود شده است تا فضای دیسک بدون کنترل مصرف نشود.

1. فایل تنظیمات را بسازید و دسترسی آن را محدود کنید:

   ```bash
   cp clubmax.production.env.example clubmax.production.env
   chmod 600 clubmax.production.env
   ```

2. تمام مقادیر `REPLACE_...`، آدرس سرور و URLهای عمومی را در آن تغییر دهید.
3. imageها را بسازید و سرویس‌ها را اجرا کنید:

   ```bash
   docker compose --env-file clubmax.production.env -f compose.production.yaml build --pull
   docker compose --env-file clubmax.production.env -f compose.production.yaml up -d --wait
   ```

   همین فرمان‌ها با `make docker-build` و `make docker-up` نیز در دسترس‌اند.

4. وضعیت و logها را بررسی کنید:

   ```bash
   docker compose --env-file clubmax.production.env -f compose.production.yaml ps
   make docker-logs
   ```

برای توقف بدون حذف داده‌ها از `make docker-down` استفاده کنید. از اجرای `docker compose down --volumes` روی سرور اصلی خودداری کنید، زیرا volumeهای دائمی دیتابیس و فایل‌ها را حذف می‌کند. این Compose در مرحله فعلی پورت‌های 3001 و 8081 را منتشر می‌کند؛ HTTPS و اتصال دامنه باید در مرحله بعد با reverse proxy روی پورت‌های 80 و 443 اضافه شود.
